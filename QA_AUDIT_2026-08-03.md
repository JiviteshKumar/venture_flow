## Findings

### QA-001 — High — Groq provider error and internal account metadata are returned to users

**Evidence:** the ShieldAI report returned `200` but included a `Synthesis note` with Groq’s rate-limit response, including the organisation identifier, service tier, daily-token limit, used-token count, retry timing, and billing URL.

**Steps to reproduce:**

1. Exhaust or approach the Groq daily token limit.
2. Submit a valid deck such as `ShieldAI_Cyber_SeriesA.pdf`.
3. Read `ai_analysis` in the `/analyze` response or report UI.

**Expected:** a generic, user-safe degradation message with server-side diagnostics only in logs.

**Actual:** the raw provider exception is interpolated into the customer-facing memo.

**Affected code:** `ventureflow_agent.py`, `_fallback_ai_analysis()`.

### QA-002 — High — client request can time out while the server continues and persists a report

**Evidence:** `UrbanHarvest_SeriesA.pdf` uploaded successfully, then `/analyze` exceeded a 150-second client timeout. A subsequent read-only Neon query showed a newly persisted UrbanHarvest report anyway.

**Impact:** users see a failed or indefinitely loading submission, retry it, and create duplicate reports/costs while the original job still runs.

**Affected code:** synchronous `POST /analyze` path in `api.py`; frontend timeout/progress handling in `frontend/src/services/apiClient.ts` and `AppContext.tsx`.

### QA-003 — High — new specialist agents silently fall back, yet reports still receive high scores

**Evidence:** the persisted ShieldAI and UrbanHarvest reports had `market`, `team`, `bull_case`, and `bear_case` confidence `0`; all claims were `NOT_ENOUGH_INFO`; final scores were nevertheless `80` and `85` respectively.

**Expected:** unsuccessful specialist analysis or all-unverified claims should visibly degrade the report and materially cap confidence/score.

**Actual:** fallback output is treated as a normal completed report, yielding deceptively strong scores.

**Affected code:** `agents/investment_agents.py`, `ventureflow_agent.py` final-score calculation.

### QA-004 — High — “Competitor Insights” displays unrelated hard-coded companies

**Steps to reproduce:** run any non-medical deck, then open **Competitor Insights**.

**Expected:** competitors should come from report/Neon data or the screen should state that no validated competitors are available.

**Actual:** the page renders static companies such as Viz.ai, Aidoc, Caption Health, Lunit, and Enlitai regardless of the submitted sector.

**Affected file:** `frontend/src/pages/Analysis.tsx`.

### QA-005 — Medium — persisted reports do not survive a browser refresh/new session in the UI

**Evidence:** Neon contained reports for all ten submitted company names, while a direct fresh visit to `/analysis` displayed **No analysis yet**. There is no endpoint or frontend workflow to list/load saved reports.

**Expected:** persistence should enable a user to reopen saved analyses.

**Actual:** report state exists only in the live React context.

**Affected code:** `frontend/src/context/AppContext.tsx`, `api.py` (missing report retrieval endpoint).

### QA-006 — Medium — unknown frontend paths render a blank content area

**Steps to reproduce:** open `https://venture-flow-w8hf.vercel.app/not-a-route`.

**Expected:** an explicit 404/not-found page with a route back to the dashboard.

**Actual:** sidebar renders but the main element is empty.

**Affected file:** `frontend/src/App.tsx` (no catch-all route).

### QA-007 — Medium — database stats API contract does not match the TypeScript client contract

**Evidence:** `GET /database/stats` returned `{"companies":8,"dd_reports":11,"portfolio_investments":0}`. `frontend/src/services/apiClient.ts` declares unrelated fields such as `documents`, `sentiment_records`, and `visual_assets`.

**Impact:** any future consumer of `api.getStats()` receives a structurally incompatible result.

### QA-008 — Medium — PDF claim extraction merges unrelated slide/table fragments

**Evidence:** LearnLoop generated a claim beginning `Classroom pacing leaves both Quality 1-on-1 tutoring costs ₹500...`, combining multiple columns into one assertion. The verifier appropriately returned `NOT_ENOUGH_INFO`, but the input is not a meaningful claim.

**Expected:** table/multi-column extraction should preserve layout or discard malformed fragments.

**Affected file:** `pdf_extractor.py`, sentence splitting/claim heuristics.

### QA-009 — Medium — rate limiter counts invalid requests and is process-local

**Evidence:** a burst of malformed requests produced `429` after the available request budget. Validation failures therefore consume the same limit as valid submissions. The limiter is an in-memory dictionary, so it resets across instances/redeploys and cannot coordinate scaled workers.

**Affected file:** `api.py` rate-limit middleware.

### QA-010 — Medium — public analysis and database-stat endpoints have no authentication or tenancy boundary

**Evidence:** all tested API endpoints are publicly callable; no authentication fields or dependency are present. The database contains cross-run report records without a user/account field.

**Impact:** if this moves beyond a demo, any caller can spend Groq quota and shared report data cannot be isolated by user.

### QA-011 — Low — loading labels are time-based rather than actual server-stage events

**Evidence:** frontend stages are scheduled with `setTimeout`; no job/status endpoint or server-sent progress events exist.

**Impact:** the interface can show an advanced stage while the server is stalled, rate-limited, or still on an earlier task.

### QA-012 — Low — mobile/tablet DOM loads cleanly, but layout needs visual-device QA

Both 390 px and 768 px route checks loaded with no console errors. The current automated run did not establish touch ergonomics or visual overflow, so Chrome/Firefox manual-device validation remains open.

## Security observations

- No API key or Neon connection string was found in tracked source or frontend environment templates.
- The tested arbitrary CORS origin was rejected; the Vercel origin preflight succeeded.
- React rendering does not use `dangerouslySetInnerHTML`, and database queries use bound parameters. No direct XSS or SQL injection vulnerability was demonstrated in the tested paths.
- The raw Groq provider error leak in QA-001 is still sensitive operational-information exposure.

## Prioritized fix list

1. **Stop returning raw Groq exceptions**; use generic client errors and structured server logging.
2. **Convert analysis to an asynchronous job model**: queue job, persist stage/status, poll or stream progress, support cancellation/idempotency, and prevent duplicate runs.
3. **Make score/confidence depend on completed evidence**; cap scores when specialist calls fail or all claims are unverified.
4. **Replace static competitor/market/funding UI data** with report-backed data or explicit empty states.
5. **Add report history/retrieval endpoints and user/session ownership** so Neon persistence is usable and tenant-safe.
6. **Improve PDF layout/claim extraction**, especially multi-column slides, and preserve claim-to-page/source provenance.
7. **Align `/database/stats` TypeScript and FastAPI contracts**.
8. **Add a catch-all frontend 404 route** and real backend stage-progress events.
9. **Use a shared rate limiter** (Redis/managed store) and decide whether rejected requests should count.
10. **Add authentication, authorization, quotas, and a data-retention policy** before exposing the service beyond a demo.

## Remediation

- **QA-004:** Replaced fabricated competitor/funding rows with API-backed comparable companies and an explicit empty state. (`74c6e97c0`)
- **QA-001:** Provider exceptions are logged server-side and replaced with generic user-facing fallback messages. (`23559fdb3`)
- **QA-003:** Incomplete evidence runs are flagged and their scores are capped at 30; the UI shows a warning. (`b222f0760`)
- **QA-005:** Added saved-report list/detail endpoints and a dashboard history list that reopens reports. (`6476cc2eb`)
- **QA-002:** Added persistent FastAPI background jobs with polling status endpoints to remove the long-running client request. (`a8aad5647`)
